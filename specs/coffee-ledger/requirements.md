# 珈琲台帳（coffee-ledger） 要件定義

## 概要

職場などで共同購入しているコーヒーについて、誰が何杯飲み、いくら支払ったかを記録する台帳である。利用者は自分の名前を選んで飲用と支払を記録し、管理者は一杯単価・利用者・集めた代金（徴収済み金額）と金庫の現金を管理する。

本要件は、既存実装（`sample/coffee-ledger`）の振る舞いを整理したものである。

## 用語

| 用語 | 説明 |
|------|------|
| 人 | 台帳の利用者。名前、表示順、利用停止の有無を持つ |
| 利用中の人 | 利用停止していない人 |
| 一杯単価 | コーヒー 1 杯の代金（円、1 以上の整数）。システムで 1 つだけ持つ |
| 飲用 | 人がコーヒーを 1 杯飲んだ記録。記録時点の一杯単価を持つ |
| 支払 | 人が代金を支払った記録。支払額（円）を持つ |
| 取り消し | 飲用または支払を無効にすること。記録は消さず、取り消した日時を残す |
| 未払い代金 | 人ごとの「取り消していない飲用の単価合計 − 取り消していない支払の合計 + 未払い修正による増減の合計」。0 を下回る場合は 0 とする |
| 未払い修正 | 管理者が人の未払い代金を任意の額に直すこと。修正前の額・修正後の額・事由を残す |
| 未徴収金額 | 全員（利用停止した人を含む）の未払い代金の合計 |
| 徴収済み金額 | 最後の金庫収納より後に記録された、取り消していない支払の合計。金庫収納が一度もない場合は、取り消していない支払の全合計 |
| 金庫収納 | 徴収済み金額の全額を金庫に移すこと |
| 金庫操作 | 金庫の現金を、事由を添えて入金または出金すること |
| 金庫金額 | 「金庫収納の合計 + 金庫操作の入金合計 − 金庫操作の出金合計」。0 を下回る場合は 0 とする |
| 操作記録 | 台帳のデータを変えた操作の記録（日時、操作の種類、内容） |
| 一般機能 | 利用者が飲用・支払を記録する機能 |
| 管理機能 | 一杯単価、人、金庫、集計、操作記録を扱う機能 |
| 管理パスワード | 管理機能に入る前に入力を求める合言葉。利用者を識別する認証ではない |

## 要件一覧

### 一般機能

### REQ-001: 一杯単価と現在日時の表示

一般機能を表示している間、システムは一杯単価と、日本時間の現在日時（秒まで）を表示すること。一杯単価が未登録の場合、システムは単価が未登録であることを表示すること。

**受け入れ条件**

- 一杯単価が登録済みのとき、「一杯 100円」のように金額が表示される。
- 一杯単価が未登録のとき、「単価未登録」と表示される。
- 現在日時は `YYYY-MM-DD HH:mm:ss` 形式の日本時間で表示され、1 秒ごとに更新される。

### REQ-002: 利用中の人の一覧

一般機能を表示したとき、システムは利用中の人を表示順の昇順に一覧表示すること。各人について、名前、未払い代金、最後の飲用の日時を表示すること。

**受け入れ条件**

- 利用停止した人は一覧に表示されない。
- 各人の未払い代金が「1,234円」の形式で表示される。
- 最後の飲用の日時は `YYYY-MM-DD HH:mm` 形式の日本時間で表示される。飲用が無い人は「—」と表示される。
- 最後の飲用が取り消し済みの場合、その日時は取り消し済みと分かる見た目（取り消し線）で表示される。
- 利用中の人が 0 人のとき、「利用中の人はいません。」と表示される。
- 一覧は画面全体をスクロールさせずに、全員を 1 画面に収めて表示する。

### REQ-003: 飲用の記録

利用者が一覧の人を指定して飲用を記録したとき、システムはその人の飲用を、その時点の一杯単価と日時で記録すること。記録後、システムは「飲みました。」と通知し、利用者が確認するまで他の操作を受け付けないこと。

**受け入れ条件**

- 記録した飲用の単価は、記録時点の一杯単価である。後で一杯単価を変えても、記録済みの飲用の単価は変わらない。
- 記録後、その人の未払い代金が単価の分だけ増え、最後の飲用の日時が更新される。
- 「飲みました。」の通知を確認（OK）するまで、一覧の操作はできない。
- 一杯単価が未登録の場合、飲用を記録できない。
- 利用停止した人の飲用は記録できない。

### REQ-004: 最後の飲用の取り消し

利用者が一覧の人の最後の飲用の取り消しを指示したとき、システムはその飲用を取り消すこと。ただし、取り消すと未払い代金が 0 を下回る（支払が飲用代金を超える）場合、システムは取り消しを拒否し、理由を表示すること。

**受け入れ条件**

- 一般機能から取り消せるのは、各人の最後の飲用だけである。
- 最後の飲用が無い、または既に取り消し済みの場合、取り消しはできない。
- 取り消し後、その人の未払い代金が単価の分だけ減る。
- 取り消すと未払い代金が 0 未満になる場合、「この飲用を取り消すと支払合計が飲用代金を超えます。」と表示され、取り消されない。

### REQ-005: 支払の記録

利用者が未払い代金のある人を指定して支払を始めたとき、システムはその人の名前と未払い代金を示し、支払額を入力させること。支払額の確定を指示されたとき、システムは支払額が 1 円以上かつ未払い代金以下の場合に限り、支払を記録すること。

**受け入れ条件**

- 未払い代金が 0 の人は、支払を始められない。
- 支払額の初期値は、その人の未払い代金の全額である。
- 支払額は 10 円単位で増減できる。
  - 増やすとき: 10 円加える。ただし未払い代金を上限とする。
  - 減らすとき: 10 円の倍数でない額は、10 円の倍数に切り下げる。10 円の倍数の額は 10 円減らす。いずれも 10 円を下限とする。
  - 未払い代金が 10 円未満のときは、支払額は未払い代金に固定される。
- 支払額が未払い代金を超える場合は記録されず、「支払額が未払い代金を超えています。」と表示される。
- 記録後、その人の未払い代金が支払額の分だけ減り、徴収済み金額が支払額の分だけ増える。
- 支払を記録せずに閉じることができる。

### REQ-006: 直近の支払の取り消し

支払の入力中、その人の直近の支払が取り消し済みでない場合、システムはその支払の日時と金額を表示すること。利用者がその支払の取り消しを指示したとき、システムはその支払を取り消すこと。

**受け入れ条件**

- 直近の支払が無い、または取り消し済みの場合、直近の支払は表示されない。
- 取り消し後、その人の未払い代金が支払額の分だけ増える。
- 取り消した支払が最後の金庫収納より後のものであれば、徴収済み金額が支払額の分だけ減る。

### 管理機能

### REQ-007: 管理パスワードによる管理機能への入場

利用者が管理機能に入ろうとしたとき、管理パスワードの入力が済んでいない場合、システムは管理パスワードの入力を求めること。入力値が設定値と一致した場合、システムは管理機能へ進めること。利用者が管理機能の外（一般機能）へ移ったとき、システムは再び管理パスワードの入力を求める状態に戻すこと。

**受け入れ条件**

- 管理パスワードを入力せずに管理機能を表示することはできない。
- 入力値が設定値と一致しないとき、「パスワードが正しくありません。」と表示され、管理機能へ進まない。
- 入力が一致したとき、入場しようとしていた管理機能の画面へ進む。
- 入力をやめた（キャンセルした）とき、一般機能へ戻る。
- 一般機能へ移った後に管理機能へ入るときは、再度入力が必要である。
- 管理パスワードの設定値は、コードに埋め込まず設定値として持つ。

### REQ-008: 一杯単価の登録と変更

管理者が一杯単価を保存したとき、システムは入力値が 1 以上の整数の場合に一杯単価を登録（未登録時）または変更（登録済み時）すること。

**受け入れ条件**

- 1 以上の整数でない値は保存できない。
- 未登録のとき、入力の初期値は 100 である。登録済みのとき、入力の初期値は現在の一杯単価である。
- 変更は以後の飲用にだけ反映され、記録済みの飲用の単価は変わらない。
- 登録と変更は、それぞれ操作記録に残る（変更は変更前と変更後の額を残す）。

### REQ-009: 徴収状況の表示

管理機能を表示したとき、システムは未徴収金額、徴収済み金額、金庫金額を表示すること。

**受け入れ条件**

- 3 つの金額が「1,234円」の形式で表示される。
- 各金額は、用語の定義どおりに計算される。

### REQ-010: 金庫収納

管理者が金庫収納を指示し、確認に同意したとき、システムは徴収済み金額の全額を金庫収納として記録すること。徴収済み金額が 0 の場合、システムは金庫収納を拒否すること。

**受け入れ条件**

- 実行前に「徴収済み ○円 を金庫に収めます。よろしいですか？」の確認が出る。同意しなければ記録しない。
- 収納後、金庫金額が収納額の分だけ増え、徴収済み金額が 0 になる。
- 徴収済み金額が 0 のときは金庫収納できない。
- 金庫収納の履歴（日時と金額）が新しい順に表示される。履歴が無いときは「金庫収納はまだありません。」と表示される。

### REQ-011: 金庫操作（入金・出金）

管理者が事由、入金または出金の別、金額、事由の日付を入力して記録を指示し、確認に同意したとき、システムは金庫操作を記録すること。出金額が金庫金額を超える場合、システムは記録を拒否すること。

**受け入れ条件**

- 事由は前後の空白を除いて 1〜200 文字である。
- 金額は 1 以上の整数である。
- 事由の日付の初期値は、日本時間の今日である。
- 入金または出金の初期値は入金である。
- 実行前に事由・入出金の別・金額を示した確認が出る。同意しなければ記録しない。
- 入金すると金庫金額が増え、出金すると金庫金額が減る。
- 出金額が金庫金額を超える場合は記録されず、「出金額が金庫金額を超えています。」と表示される。

### REQ-012: 人の登録

管理者が名前を入力して登録を指示したとき、システムは前後の空白を除いた名前が 1〜100 文字で、既存の人（利用停止した人を含む）と重複しない場合に、人を登録すること。

**受け入れ条件**

- 登録した人は、表示順の末尾に加わる。
- 同じ名前の人がいる場合は登録されず、「同じ名前の人が既に登録されています。」と表示される。
- 名前が空（空白のみを含む）の場合は登録できない。
- 登録を指示すると、名前の入力欄は空に戻る。

### REQ-013: 人の利用停止

管理者が利用中の人の利用停止を指示したとき、システムはその人を利用停止にすること。

**受け入れ条件**

- 利用停止した人は、一般機能の一覧に表示されず、飲用を記録できない。
- 利用停止した人は、管理機能の人の一覧に「停止」の印付きで表示され続ける。
- 利用停止した人の未払い代金は、未徴収金額に含まれ続ける。
- 利用停止した人を利用中に戻す操作は無い。

### REQ-014: 表示順の変更

管理者が人の一覧で、ある人を一つ上または一つ下へ移すよう指示したとき、システムはその人と隣の人の表示順を入れ替えること。

**受け入れ条件**

- 表示順は、利用停止した人を含む全員で 1 から連番になる。
- 先頭の人は上へ、末尾の人は下へ移せない。
- 変更した表示順は、一般機能の一覧にも反映される。

### REQ-015: 人の記録の参照

管理者が人の一覧から人を選んだとき、システムはその人の未払い代金、飲用記録、支払記録を表示すること。

**受け入れ条件**

- 飲用記録は、日時と単価を新しい順に表示する。取り消し済みの記録は「取消済み」の印付きで表示する。
- 支払記録は、日時と金額を新しい順に表示する。取り消し済みの記録は「取消済み」の印付きで表示する。
- 管理機能のこの表示からは、飲用・支払の記録と取り消しはできない（参照のみ）。
- 記録が無いときは「飲用記録はまだありません。」「支払記録はまだありません。」と表示される。

### REQ-016: 未払いの修正

管理者が選んだ人について、新しい未払い代金と事由を入力して修正を指示し、確認に同意したとき、システムはその人の未払い代金を新しい額に修正すること。

**受け入れ条件**

- 新しい額は 0 以上の整数で、現在の未払い代金と異なる額である。
- 事由は前後の空白を除いて 1〜200 文字である。
- 実行前に「○○ の未払いを ○円 から ○円 に修正します。事由「…」。よろしいですか？」の確認が出る。同意しなければ修正しない。
- 修正後、その人の未払い代金は新しい額になり、未徴収金額にも反映される。
- 修正前の額・修正後の額・事由・日時が記録として残る。

### REQ-017: 集計（金額の推移）

管理者が集計を表示したとき、システムは現在の未徴収金額・徴収済み金額・金庫金額と、金額を変えた出来事の一覧を新しい順に表示すること。一覧の各行には、出来事の直後の 3 つの金額を表示すること。

**受け入れ条件**

- 対象の出来事は、飲用、飲用の取り消し、支払、支払の取り消し、金庫収納、金庫操作（入金・出金）、未払い修正である。
- 各行に、日時、出来事の種類、内容（人の名前、金額、事由、事由の日付、修正前後の額のうち該当するもの）、出来事の直後の未徴収金額・徴収済み金額・金庫金額を表示する。
- 各行の金額は、古い出来事から順に積み上げて求める。各金額は 0 を下回らない。
- 出来事が無いときは「変化はまだありません。」と表示される。

### REQ-018: 操作記録

システムは、台帳のデータを変えた操作のたびに、日時・操作の種類・内容を操作記録として残すこと。管理者が操作記録を表示したとき、システムは操作記録を新しい順に一覧表示すること。

**受け入れ条件**

- 記録する操作は、人の登録、人の利用停止、表示順の変更、一杯単価の登録、一杯単価の変更、飲用の記録、飲用の取り消し、支払の記録、支払の取り消し、金庫収納、金庫操作、未払い修正である。
- 各行に、日時、操作の種類、内容（人の名前、金額、変更前後の額、事由など）を表示する。
- 操作が失敗した場合、操作記録は残らない。
- 操作記録が無いときは「操作記録はまだありません。」と表示される。

### 共通

### REQ-019: 日時と金額の表し方

システムは常に、日時を日本時間で記録・表示し、金額を円単位の整数として扱うこと。

**受け入れ条件**

- 一覧・記録の日時は `YYYY-MM-DD HH:mm` 形式の日本時間で表示される（REQ-001 の現在日時を除く）。
- 金額は 3 桁ごとの区切りを付け、末尾に「円」を付けて表示される。

### REQ-020: 失敗時の扱い

操作が失敗した場合、システムはその操作によるデータの変更を一切残さず、失敗の理由を利用者に表示すること。

**受け入れ条件**

- 失敗した操作の途中までの変更（記録や操作記録）は残らない。
- 失敗の理由が日本語のメッセージで表示される。
- 通信に失敗した場合は「通信に失敗しました。」、想定外の失敗の場合は「処理に失敗しました。」と表示される。

### REQ-021: 同時操作での整合性

複数の利用者が同時に操作した場合でも、システムは未払い代金・徴収済み金額・金庫金額の整合を保つこと。

**受け入れ条件**

- 同じ人への飲用・支払・取り消し・未払い修正が同時に行われても、未払い代金を超える支払や、0 を下回る未払い代金を生む取り消しは記録されない。
- 金庫収納と金庫操作が同時に行われても、金庫金額を超える出金や、二重の金庫収納は記録されない。
- 人の登録と表示順の変更が同時に行われても、名前と表示順は重複しない。

## 認証の要否

認証しない。利用者のログインやユーザ管理は行わず、全員が同じ台帳データを扱う。

管理機能への入場時に管理パスワードを求める（REQ-007）が、これは誤操作を防ぐための簡易的な入場確認であり、利用者を識別する認証ではない。

## スコープ外

- 利用者のログイン、ユーザ管理、利用者ごとのデータの分離
- 利用停止した人を利用中に戻すこと、人の名前の変更、人の削除
- 一般機能からの、最後の飲用より前の飲用の取り消し
- 金庫収納・金庫操作・未払い修正の取り消しや変更
- 記録の削除
- 複数の一杯単価（メニューやサイズ別の単価）
- データの出力（CSV など）や印刷
