# 画面の見た目、画面分割とナビ

> 元Cursorルールでの適用範囲: `specs/**/ui-design.md`、`src/features/**/frontend/**/*.{vue,css,scss,ts}` を編集するとき。コンテンツの部品は各機能の `ui-design.md` で決める。

**見た目の正は既存実装 `sample/coffee-ledger/frontend/`（特に `src/style.css`）である。** 本ルールはその見た目を文書にしたもの。本ルールと既存実装が食い違う場合は既存実装に合わせ、本ルールを直す。

`rules/31-web-app-responsive-layout-spec.md` と食い違う場合は、本ルールを優先する。

**このルールが決めること:** 色・余白・部品の見た目、画面の分割（ヘッダ / コンテンツ）、ナビの形。
**各機能の `ui-design.md` が決めること:** コンテンツに何を置くか、画面間の遷移先。同じ役割のものは、既存と同じ見た目で設計する。


## 前提

- ページ全体はスクロールさせない（`html, body { height: 100%; overflow: hidden; }`）。スクロールはコンテンツ領域の内側で行う。
- 対象: PC とスマートフォン。想定ブラウザ: Google Chrome、Safari。
- 画面幅によるレイアウトの切り替え（ブレークポイント）は設けない。PC とスマートフォンで同じ分割・同じナビを使う。
- 文字の基準はブラウザ既定（16px）。サイズは `rem` で指定する。
- CSS は `frontend/src/style.css` の 1 ファイルに置き、クラス名で部品の見た目を揃える。部品ごとの scoped CSS は使わない。


## 思想

コーヒーを思わせる茶系の配色で、情報（名前と金額）を主役にする。一般の画面は「1 画面で全員が見えて、1 回のタップで記録できる」ことを最優先にする。

- 学習コストが低い（ボタンは文字で意味を示す）
- 操作ミスしにくい（完了の通知、金額に関わる管理操作は確認を挟む）
- 同じ役割のものは同じ見た目にする

避けること: 高彩度の色、グラデーション、目的のないアニメーション、茶系から外れた独自色。


## 画面分割とナビ

全画面で、上端のヘッダ（ナビを兼ねる）とコンテンツの 2 段に分ける。左ナビや下端ナビは置かない。

```
┌──────────────────────────────────────┐
│ 珈琲台帳                  飲む   管理 │  ← ヘッダ（ナビ）
├──────────────────────────────────────┤
│ Content                              │
└──────────────────────────────────────┘
```

### ヘッダ（ナビ）

- 面 `#5b3318`、文字 `#fff`、余白 `0.45rem 1rem`。高さは内容なり（固定しない）。
- 左にブランド名（太字、一般の画面へのリンク）、右にナビのリンク（文字のみ、下線なし、間隔 `1rem`）。
- ナビのリンクは主要な入口だけ（既存: 「飲む」「管理」）。管理の下位画面へのリンクはヘッダに置かず、管理トップのコンテンツに置く。
- 管理パスワードの入力画面にも同じヘッダを出す。

### コンテンツの型

コンテンツは次の 2 つの型のどちらかにする。

**全面型（一般の画面）** — 画面いっぱいに使い、コンテンツ自体もスクロールさせない。

```
┌──────────────────────────────────────┐
│ 一杯 100円            2026-09-24 14:12:05 │ ← 上部バー
├──────────────────┬───────────────────┤
│ 名前 未払 飲む 日時 🗑 │ 名前 未払 飲む 日時 🗑 │
│ 名前 未払 飲む 日時 🗑 │ 名前 未払 飲む 日時 🗑 │ ← 2 列の行一覧
│        …         │        …          │   （行の高さを均等に縮めて全員を収める）
└──────────────────┴───────────────────┘
```

- 余白 `0.35rem 0.8rem 0.4rem`、幅の上限なし。
- 上部バー: 左に単価、右に現在日時（`0.95rem`、太め、色 `#5b3318`）。エラーは上部バー内に小さく出す（`.error.compact`）。
- 行一覧: 2 列のグリッド（列間 `1.2rem`、中央に `#cbbba8` の 1px の区切り線）。行の高さは均等（`minmax(0, 1fr)`）にし、人数が増えても 1 画面に収める。
- 行: `名前 | 未払いボタン | 飲むボタン | 最後の飲用日時 | 取り消しアイコン` の 5 列。行の下端に `#efe4d6` の 1px 線。名前は太字で、はみ出す場合は `…` で省略。

**ページ型（管理の画面、管理パスワードの入力画面）** — 中央寄せの 1 カラム。コンテンツの内側だけスクロールする。

- 幅の上限 `880px`、中央寄せ、余白 `1.2rem`。
- 先頭にページ見出し（`h1`）。下位画面は見出しの上に「← 管理トップ」のリンクを置く。
- 管理トップは、見出しの下に下位画面へのリンク（横並び、間隔 `1.4rem`）を置く。
- 内容はパネル（後述）を縦に積む。

## 部品の見た目

| 部品 | クラス | 見た目 |
|------|--------|--------|
| ページ見出し | `h1` | ブラウザ既定 |
| パネル見出し / 小見出し | `h2` / `h3` | ブラウザ既定 |
| パネル | `.panel` | 面 `#fff`、角丸 `12px`、余白 `1rem 1.2rem`、上下の間隔 `1rem`、影 `0 1px 4px rgba(0,0,0,0.08)` |
| 主ボタン | `.primary` | 面 `#6b3f1d`、文字 `#fff`、枠なし、角丸 `8px`、余白 `0.45rem 0.9rem` |
| 通常ボタン | （クラスなし） | ブラウザ既定のボタン（閉じる、キャンセル、一つ上へ / 一つ下へ、−、＋） |
| テキストボタン | `.link` | 枠・面なし、文字 `#6b3f1d`、下線あり（取り消し、利用停止） |
| アイコンボタン | `.icon-btn` | 枠・面なし、文字 `#7a5a3a`、ホバーで `#a12626`。アイコンは 16×16px のインライン SVG（`fill="currentColor"`） |
| 未払いボタン | `.unpaid-btn` | 面 `#efe4d6`、文字 `#6b3f1d`、太字 `0.88rem`、角丸 `8px`。金額をラベルにする |
| 飲むボタン | `.drink-btn` | 面 `#6b3f1d`、文字 `#fff`、太字 `0.88rem`、角丸 `8px` |
| 無効なボタン | `:disabled` | 不透明度 `0.5`、カーソル `not-allowed` |
| 入力欄 | `input` | 余白 `0.35rem 0.5rem`、枠 1px `#cbbba8`、角丸 `6px` |
| ラベル | `label` | 項目名を入力欄の上に置く（縦並び、間隔 `0.2rem`） |
| 横並びフォーム | `.row` | 横並び、下揃え、間隔 `0.8rem`、折り返し可（名前 + 登録、金額 + 保存など、項目が 1 つのもの） |
| 縦並びフォーム | `.vault-form` | 縦並び、間隔 `0.8rem`、幅の上限 `22rem`（項目が複数のもの） |
| 選択肢 | `.direction-row` | ラジオボタンを横並び。枠なしの `fieldset` と `legend` で項目名を付ける |
| 記録の一覧 | `.records` / `.people-admin` | 行頭記号なし。行は左右両端揃え、余白 `0.4rem 0`、下端に `#efe4d6` の 1px 線 |
| 表 | `.log-table` | 幅 100%、左揃え、上揃え、セル余白 `0.4rem 0.3rem`、行の下端に `#efe4d6` の 1px 線 |
| バッジ | `.badge` | 面 `#eee`、文字 `#555`、`0.8rem`、角丸は丸型（取消済み、停止） |
| 取り消し済み | `.cancelled` | 文字 `#888`、取り消し線 |
| 強調した金額 | `.price` / `.unpaid` | `1.1rem`、太さ 600。単価が未登録なら `.price.missing`（`#a12626`） |
| 補足 | `.muted` | 文字 `#7a6a5c` |
| エラー | `.error` | 文字 `#a12626`、面 `#fdeeee`、余白 `0.6rem 0.8rem`、角丸 `8px` |
| 一覧の名前ボタン | `.name-select` | 枠・面なし、左揃え。行を選ぶためのボタン（名前がラベル） |

- ボタンは文字ラベルを基本とする。アイコンだけのボタンは「取り消し」（ゴミ箱のアイコン）に限り、必ず `aria-label` で意味を示す。


## モーダル / 確認

- モーダル: 背景 `rgba(43,33,24,0.45)` で画面を覆い、中央に面 `#fff`、角丸 `14px`、余白 `1.2rem 1.4rem`、幅 `280px`〜`90vw`、影 `0 12px 32px rgba(0,0,0,0.2)`。`role="dialog"`、`aria-modal="true"` を付ける。
- 背景をクリックしても閉じない。閉じる操作はモーダル内のボタンだけにする。
- 完了の通知（例:「飲みました。」）は、モーダルに `1.4rem` 太字・中央揃えの文言と「OK」ボタンを置く。OK を押すまで他の操作を受け付けない。
- 入力を伴う操作（例: 支払）は、モーダルに見出し（`1.1rem` 太字）、入力、ボタン（確定の主ボタン + 閉じる）を置く。
- 金額や記録を変える管理の操作（金庫収納、金庫操作、未払い修正）は、実行前にブラウザの確認ダイアログ（`window.confirm`）で内容を示し、同意を得る。


## 状態の見た目

| 状態 | 見た目 |
|------|--------|
| 読込中 | 専用の表示はしない。初期値（空の一覧、0 円）のまま表示し、読み込み後に置き換える |
| 処理中 | 操作ボタンを無効にし、二重の送信を防ぐ |
| 空 | 一覧の位置に `.muted` で「〜はまだありません。」（例:「飲用記録はまだありません。」）。一般の画面は「利用中の人はいません。」 |
| エラー | ページ型は見出しの下に `.error`。全面型は上部バーに `.error.compact`。API が返したメッセージを出す |
| 成功 | 成功メッセージは出さない。表示内容を読み直して結果を反映する（飲用の記録だけは完了のモーダルを出す） |


## 文言

- 日時は日本時間 `YYYY-MM-DD HH:mm`（現在日時だけ秒まで）。金額は `1,234円`。
- 一覧の区切りは `·`（例: `2026-09-24 14:12 · 100円`）。
- 既存のボタンの文言: 飲む、OK、支払い確定、閉じる、保存、金庫に収める、記録する、修正する、登録、利用停止、一つ上へ、一つ下へ、取り消し、進む、キャンセル。同じ意味の操作は同じ語を使う。


## アクセシビリティ

- アイコンだけのボタンには `aria-label` を付ける。
- 刻々と変わる表示（現在日時）には `aria-live="polite"` を付ける。
- フォーカス表示はブラウザ既定のものを消さない。
