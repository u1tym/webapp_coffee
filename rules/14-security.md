# セキュリティ方式

> 元Cursorルールでの適用範囲: 常時適用

## 利用技術

- 開発環境では、httpを用いる。
- 本番環境では、httpsを用いる。

## 認証

- **認証しない。** ログイン、ユーザ管理、セッションは実装しない。
- ユーザ表・セッション表・機能マスタ・メニュー割当は作らない。
- 業務データにユーザIDを持たせない。全員が同じ機能のデータを扱う。
- API に未ログイン（401）・権限なし（403）の判定は設けない。
- SPEC では、`requirements.md` の「認証の要否」、`design.md` の「認証 / 認可」節、`api-design.md` の共通節に「認証しない」と書き、各エンドポイントの認証は「不要」とする。

## 管理パスワード（簡易ロック）

要件で求められた場合に限り、管理用の画面へ入る前に合言葉（管理パスワード）の入力を求めてよい。

- 誤操作を防ぐための入場確認であり、認証ではない。API 側では判定しない。
- 設定値はフロントの `.env` に持つ（名前は `VITE_<FEATURE>_ADMIN_PASSWORD`。例: `VITE_COFFEE_LEDGER_ADMIN_PASSWORD`）。コードに平文で埋め込まない。
- フロントの設定値はビルド成果物に含まれ、利用者から読める。秘密を守る手段として扱わない。
- 管理用の画面から一般の画面へ移ったら、再び入力を求める状態に戻す。

## CORS

- 許可オリジンは `CORS_ORIGINS` で具体指定する。`*` は使わない。

## 機能ごとの実装

- 他機能の API や Python を import しない。

## 秘密情報

- DB のパスワード等の秘密情報は、各機能の `backend/.env` に持つ。コードに平文で埋め込まない。
- 秘密情報はログに出さない（`rules/16-logging.md`）。
